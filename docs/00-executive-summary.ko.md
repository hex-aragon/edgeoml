# EdgeOML 실행 요약

## 이번에 확정한 프로젝트

**EdgeOML — 온디바이스 배포 이후에도 OML 모델 핑거프린트가 살아 있는지 검증하는 오픈 벤치마크와 증거 영수증 규격**

핵심 질문은 단순합니다.

> OML 핑거프린트를 심은 오픈 모델을 GGUF로 변환하고 8/6/5/4/3/2비트로
> 양자화해 휴대폰과 노트북에서 실행했을 때도 동일한 모델임을 식별할 수
> 있는가?

Sentient가 명시한 온디바이스 개인 AI, 모델 검증 증명, 에이전트 신원,
프라이버시 기본값을 하나의 프로젝트로 묶는 방향입니다.

## 지금 신청할 트랙과 금액

  Android L1 증거 영수증 프로토타입

후속 연구·투자 트랙에서 규모를 키우는 편이 설득력이 높습니다.

## 가장 중요한 기술 차별점

HF BF16과 GGUF Q4를 곧바로 비교하지 않습니다.

```text
HF BF16 → GGUF BF16      변환·런타임·템플릿 차이 측정
GGUF BF16 → GGUF Q4      순수 양자화 영향 측정
```

이 통제 조건이 없으면 핑거프린트가 사라진 원인을 알 수 없습니다. 기존 OML
공개 구현은 이 경로와 음성 대조군·신뢰구간을 제공하지 않습니다.

## 과장하지 않을 것

- 앱이 모델 해시에 서명했다고 실제 그 모델이 추론했다고 주장하지 않습니다.
- Android Key Attestation과 Apple App Attest는 앱/기기/키에 대한 증거이지,
  모델 실행 자체의 완전한 증명이 아닙니다.
- “지울 수 없는 핑거프린트” 대신 제거 비용과 모델 성능 손상 곡선을 냅니다.
- “완전 오프라인 과금 보장”을 주장하지 않습니다.

이 정직한 보안 경계가 기술 심사에서 강점이 됩니다.

## 로컬 필수 관문 완료

다음 최소 결과는 Apple M4 16GB에서 실제로 실행했습니다.

1. Apache-2.0 1B급 모델 한 개
2. 핑거프린트 32~128개 삽입
3. Transformers BF16 / GGUF BF16 / Q8_0 / Q4_K_M 비교
4. 원본 모델 및 가짜 키 음성 대조군
5. 원시 JSONL, 정확한 실행 명령, 고정된 소스 리비전
6. exact-match와 95% 신뢰구간 결과

로컬 M4 16GB 장비는 GGUF 변환·양자화 추론·분석에 적합합니다. 공식 OML
학습 코드는 CUDA/DeepSpeed 중심이므로 그랜트급 학습은 NVIDIA 클라우드에서
재현하는 것이 안전합니다.

실측 exact-match는 Transformers BF16 31/32, GGUF BF16 30/32, Q8_0
31/32, Q4_K_M 28/32였습니다. 각 배포 조건에서 가짜 키 256개 중 오탐은
0건이었습니다. 원시 JSONL, Wilson 95% 신뢰구간, 실행 명령, 소스 리비전,
아티팩트 해시는 `experiments/m4-lora-pilot/`에 보존했습니다.

단, 이것은 MLX LoRA를 사용한 OML-style 가능성 파일럿입니다. Sentient의
공식 OML 전체 미세조정 재현이라고 주장하지 않습니다. 남은 제출 관문은
저장소와 결과 보고서를 공개 URL로 게시하고 신청서의 개인정보·경력
플레이스홀더를 사실로 채우는 일입니다.
